# ระบบตรวจข้อสอบปรนัยอัตโนมัติจากภาพถ่ายมือถือ (OMR Grading System)

เปลี่ยนภาพถ่ายกระดาษคำตอบจากมือถือให้เป็นคะแนนด้วย Python — ไม่ต้องใช้เครื่องสแกน และ **ไม่ใช้ฐานข้อมูล**
(ผลการตรวจเก็บเป็นไฟล์ JSON + Excel + ภาพ ในโฟลเดอร์ `results/sessions/`)

| เครื่องมือ | ใช้ทำอะไรในระบบ | โมดูล |
|---|---|---|
| **Streamlit** | หน้า UI / Dashboard | `app.py`, `components/`, `.streamlit/config.toml` |
| **YOLOv8n** (ultralytics) | ตรวจจับกรอบบริเวณที่มีปัญหา: ฝนหลายตัวเลือก / ฝนจาง / รอยลบ | `omr/detector.py`, `tools/train_yolo.py` |
| **OpenCV** | หามาร์กเกอร์และขอบกระดาษ, warp, ลบเงา, วาดผล, วัดความคม | `omr/preprocess.py`, `omr/quality.py`, `omr/annotate.py` |
| **imutils** | `four_point_transform` ปรับมุม/ระนาบภาพเมื่อใช้ขอบกระดาษ, `grab_contours`, `resize` | `omr/preprocess.py` |
| **scikit-image** | `threshold_local` (adaptive threshold), `label` + `regionprops` หาบริเวณแสงสะท้อน | `omr/preprocess.py`, `omr/quality.py` |
| **NumPy** | ภาพเป็น array, คำนวณ fill ratio / ความมั่นใจ | ทุกโมดูล |
| **SciPy** | `ndimage.gaussian_filter` ลด noise, `binary_opening` ลบจุดหมึกโดด | `omr/preprocess.py` |
| **Pandas + OpenPyXL** | ตารางคะแนน และสร้างไฟล์ Excel 4 ชีต | `omr/exporter.py`, `app.py` |
| **Python** | ภาษาหลักทั้งระบบ | — |

- ข้อสอบ 4 ตัวเลือก (A–D) ค่าเริ่มต้น 40 ข้อ (รองรับ 1–60 ข้อโดยแก้ `NUM_QUESTIONS` ใน `omr/config.py`)
- รหัสนักศึกษา 5 หลัก
- รองรับภาพเอียง ±15°, มุมกล้องไม่ตั้งฉากเล็กน้อย, แสงไม่สม่ำเสมอ, เงาบางส่วน, ภาพกลับหัว, EXIF orientation
- ตรวจจับ ไม่ฝน / ฝนหลายตัวเลือก / ฝนจาง / รหัสอ่านไม่ได้ พร้อมค่าความมั่นใจรายข้อ
- Dashboard (Streamlit) แก้ไขข้อที่ไม่มั่นใจได้ และส่งออก Excel

## สถาปัตยกรรม pipeline

```
ภาพถ่าย ──► load_image (EXIF) ──► find_markers ──► warp (1240×1754) ──► fix_orientation
                                   │ ไม่ครบ 4 มุม                              │
                                   └► find_paper ─► imutils four_point_transform┘
                                                                              ▼
            quality (เบลอ/มืด/แสงสะท้อน) ◄──┬── binarize: ลบเงา → SciPy ลด noise → scikit-image threshold_local
            YOLOv8n (กรอบที่มีปัญหา)    ◄──┤                                   → SciPy ลบจุดโดด
                                           ▼
   ไฟล์ JSON/Excel ◄── storage ◄── exporter ◄── annotate ◄── grader (+ flag จาก YOLO/แสงสะท้อน) ◄── reader
```

| โมดูล | หน้าที่ |
|---|---|
| `omr/config.py` | ค่าคงที่ทั้งหมด: layout (mm), ค่าเกณฑ์, พารามิเตอร์ภาพ, สี |
| `omr/layout.py` | คำนวณพิกัดมาร์กเกอร์/bubble (ใช้ร่วมทั้งสร้างกระดาษและอ่าน) |
| `omr/sheet_generator.py` | สร้างกระดาษคำตอบ PDF (พิมพ์) และ PNG (สร้างภาพทดสอบ) จาก layout เดียวกัน |
| `omr/preprocess.py` | หามาร์กเกอร์ 4 มุม (สำรอง: ขอบกระดาษ), perspective warp, ตรวจทิศ, ลบเงา + threshold |
| `omr/quality.py` | ตรวจภาพเบลอ/มืด และหาบริเวณแสงสะท้อนด้วย regionprops |
| `omr/detector.py` | YOLOv8n ตรวจจับกรอบปัญหาในพื้นที่คำตอบ แล้วผูกกับเลขข้อ |
| `omr/storage.py` | บันทึก/เปิด/ลบผลการตรวจเป็นไฟล์ (แทนฐานข้อมูล) |
| `omr/reader.py` | fill ratio ของ bubble, ตัดสิน OK/FAINT/MULTI/BLANK, ความมั่นใจ, รหัสนักศึกษา |
| `omr/grader.py` | อ่านเฉลย CSV, ให้คะแนน, สรุปสถิติแผ่น |
| `omr/annotate.py` | วาดผลตรวจลงภาพ |
| `omr/exporter.py` | ส่งออก Excel 4 ชีต |
| `omr/pipeline.py` | `grade_image()` รวมทุกขั้น (ไม่ crash), `regrade()`, `apply_review()` |
| `omr/models.py`, `omr/errors.py` | dataclass ผลลัพธ์ และ exception ข้อความไทย |
| `app.py` | จุดเริ่ม Streamlit dashboard: `st.navigation` เปิดหน้าตาม URL |
| `components/<หน้า>/` | แต่ละหน้าคือไฟล์ของตัวเองและมี URL ของตัวเอง: dashboard (`/`), upload, result, report, export_excel, setting (+ sidebar, shared) |
| `tools/cli.py` | ตรวจ/สร้างกระดาษจาก command line |
| `tools/synth.py` | สร้างภาพถ่ายสังเคราะห์ + ground truth |
| `tools/evaluate.py` | วัด accuracy และเวลา |
| `tools/train_yolo.py` | สร้างชุดข้อมูลสังเคราะห์ label อัตโนมัติ แล้วเทรน YOLOv8n |

**สรุปอัลกอริทึม**

1. **หามาร์กเกอร์** — ย่อภาพด้านยาว 1600 px → blur → adaptive threshold → contour ที่เป็นสี่เหลี่ยม 4 มุม
   (aspect, solidity, extent ≥ 0.80 เพื่อตัดวงกลมที่ฝน, ภายในมืดกว่าขอบรอบนอก) → ลองทุกชุด 4 ตัว
   เลือกชุดที่ขนาดใกล้กัน รูปทรงสมเหตุสมผล และกรอบใหญ่สุด
2. **Warp** — จุดกึ่งกลางมาร์กเกอร์ (จุดตัดเส้นทแยง) → ตำแหน่งตามแบบในภาพ 1240×1754 (= A4 ที่ 150 DPI)
3. **ตรวจทิศ** — มาร์กเกอร์มุมบนซ้ายมีช่องขาว 4×4 mm ถ้าพบช่องขาวที่มุมขวาล่างแทนให้หมุน 180°
   ถ้าหามาร์กเกอร์ไม่ครบ (เช่น นิ้วบังมุม) จะหาขอบกระดาษด้วย Canny + contour แล้วใช้ `imutils.four_point_transform`
   แทน แผ่นนั้นจะถูกทำเครื่องหมาย "ต้องตรวจสอบ" เพราะขอบกระดาษแม่นยำน้อยกว่ามาร์กเกอร์
4. **Binarize** — ประมาณพื้นหลังด้วย morphological close (61 px) แล้วหาร เพื่อลบเงา → SciPy `gaussian_filter`
   (σ = 1) → scikit-image `threshold_local` (mean, block 51, offset 25) → SciPy `binary_opening` 2×2 ลบจุดโดด
5. **อ่าน** — สัดส่วนพิกเซลหมึกในวงใน 75% ของ bubble → เกณฑ์ FILL/FAINT → ความมั่นใจ `(r1 − r2) / 0.40`
6. **ตรวจคุณภาพภาพ** — Laplacian variance (เบลอ), ความสว่างกระดาษ (มืด), บริเวณอิ่มตัวที่สว่างกว่ากระดาษ
   ≥ 30 ระดับ รวมกลุ่มด้วย `regionprops` (แสงสะท้อน) — ข้อที่อยู่ใต้แสงสะท้อนถูก flag
7. **YOLOv8n** — ครอปพื้นที่คำตอบจากภาพหลัง warp → ตรวจจับ `multi_mark` / `faint_mark` / `erasure`
   → ผูกกรอบกับข้อที่ทับ → ข้อนั้นถูก flag "ไม่มั่นใจ" ให้ผู้ตรวจดู (YOLO **ไม่เปลี่ยนคำตอบ** ที่อ่านจาก fill ratio)

## คำแนะนำการถ่ายภาพ

1. ให้เห็น **สี่เหลี่ยมดำ (มาร์กเกอร์) ครบทั้ง 4 มุม** ในภาพ
2. วางกระดาษบน **พื้นเรียบ** สีเข้มหรือตัดกับกระดาษ ไม่พับหรือโค้งงอ
3. **แสงสว่างพอ** หลีกเลี่ยงเงามือ/โทรศัพท์ทับมุมกระดาษ และแสงสะท้อนจ้า
4. ถือกล้องขนานกับกระดาษ **เอียงไม่เกิน 15°**
5. ใช้ไฟล์ JPG / PNG / HEIC (ไฟล์ HEIC จาก iPhone อัปโหลดได้เลย ไม่ต้องแปลงก่อน)

### ถ่ายด้วยกล้องผ่านหน้าเว็บ

- เลือก **"ถ่ายด้วยกล้อง"** ในหน้าอัปโหลดภาพ → ถ่าย → กด *Clear photo* แล้วถ่ายแผ่นถัดไป → "เริ่มตรวจ N แผ่น"
- ระบบขอภาพ 1080p จากกล้อง (เบราว์เซอร์เลือกความละเอียดที่ใกล้ที่สุดที่กล้องทำได้)
- **กล้องเปิดได้เฉพาะเมื่อเข้าเว็บผ่าน `localhost` หรือ `https://`** เบราว์เซอร์บล็อกกล้องบน `http://` ธรรมดา
  เช่น เปิดจากมือถือด้วย `http://192.168.x.x:8501` กล้องจะไม่ทำงาน — ให้ใช้ "อัปโหลดไฟล์" แทน
- บนมือถือ ปุ่ม "อัปโหลดไฟล์" มีตัวเลือก "ถ่ายรูป" ของระบบอยู่แล้ว และได้ภาพความละเอียดเต็มของกล้อง (คมกว่า)

### การเก็บข้อมูล (ไม่ใช้ฐานข้อมูล)

กด "บันทึกผล" แล้วระบบจะสร้างโฟลเดอร์ `results/sessions/<ชื่อรอบ>/` ที่มี `session.json` (ผลตรวจ, ratio ทุก bubble,
กรอบปัญหา, เฉลย), `results.xlsx` และ `images/` (ภาพหลัง warp + ภาพต้นฉบับย่อ) เปิดกลับมาแก้ไขต่อได้จากเมนู
"ส่งออก Excel" จะสำรองข้อมูลก็แค่คัดลอกโฟลเดอร์

**ความหมายสีบนภาพ annotate:** เขียว = ถูก, แดง = ผิด (วงเขียวเส้นประ = เฉลย), เหลือง = ไม่มั่นใจ/ฝนจาง,
กรอบส้มทั้งแถว = ฝนซ้ำหรือไม่ฝน, กรอบรหัสเขียว/แดง = อ่านรหัสได้/ไม่ได้,
กรอบม่วง = YOLOv8n (ชื่อคลาส + ความมั่นใจ), กรอบฟ้า = แสงสะท้อน

## YOLOv8n: เทรนโมเดลตรวจจับบริเวณที่มีปัญหา

```bash
python tools/train_yolo.py                           # 250 train / 50 val, 30 epochs, imgsz 640 (CPU ~40 นาที)
python tools/train_yolo.py --n-train 400 --epochs 60 # เทรนนานขึ้น
```

สคริปต์สร้างภาพสังเคราะห์ (เพิ่มความถี่ฝนจาง/ฝนซ้ำ/รอยลบ) → warp ด้วย pipeline จริง → ครอปพื้นที่คำตอบ →
เขียน label จากตำแหน่งที่รู้อยู่แล้ว (ไม่ต้อง label ด้วยมือ) → fine-tune จาก `models/yolov8n.pt` (COCO) →
คัดลอก best.pt ไปที่ `models/omr_problems_yolov8n.pt` ชุดข้อมูลอยู่ใน `datasets/`, log การเทรนใน `runs/`

ถ้าไม่มีไฟล์โมเดลหรือไม่ได้ติดตั้ง ultralytics ระบบยังทำงานได้ตามปกติ เพียงข้ามขั้น YOLO
(สถานะแสดงในเมนู "ตั้งค่า") เมื่อมีภาพจริง ควรเพิ่มภาพจริงที่ label แล้วลงใน `datasets/omr_problems` แล้วเทรนใหม่

รูปแบบไฟล์เฉลย (`samples/answer_key_example.csv`):

```csv
question,answer
1,A
2,B
```

## วัด accuracy

### ภาพสังเคราะห์

```bash
python tools/synth.py --n 100 --out samples/synthetic --seed 42
python tools/evaluate.py --images samples/synthetic --truth samples/synthetic/ground_truth.csv
```

รายงานบันทึกที่ `reports/eval_YYYYMMDD_HHMM.md`, รายการข้อที่อ่านผิด `reports/eval_…_errors.csv`
และภาพ annotate ของแผ่นที่มีข้อผิดใน `reports/errors/`

### ภาพถ่ายจริง

1. พิมพ์กระดาษ ให้ผู้ทดสอบฝนจริง (ควรมีทั้งฝนปกติ ฝนจาง เว้นว่าง ฝนซ้ำ) อย่างน้อย 20–30 แผ่น
2. ถ่ายด้วยมือถือหลายรุ่น หลายสภาพแสง ใส่ไว้ในโฟลเดอร์เดียว เช่น `real/`
3. สร้าง `real/ground_truth.csv` รูปแบบเดียวกับชุดสังเคราะห์:
   ```csv
   filename,student_id,q1,q2,...,q40
   IMG_0001.jpg,65001,A,,AC,D,...
   ```
   (ว่าง = ไม่ฝน, "AC" = ฝนซ้ำ, ฝนจางใช้ตัวเลือกนั้น) — รหัสที่ขึ้นต้นด้วย 0 ให้ใส่ครบ 5 หลัก
4. รัน
   ```bash
   python tools/evaluate.py --real --images real --truth real/ground_truth.csv --key real/answer_key.csv
   ```
   ผลอยู่ที่ `reports/eval_real_….md` และภาพแผ่นที่อ่านผิดใน `reports/errors_real/`

## การจูนค่า threshold

| ค่า (`omr/config.py`) | ความหมาย | อาการเมื่อควรปรับ |
|---|---|---|
| `FILL_THRESHOLD` = 0.45 | ratio ขั้นต่ำที่นับว่าฝน | ฝนเบามือจนขึ้น FAINT บ่อย → ลดลง |
| `FAINT_THRESHOLD` = 0.25 | ต่ำกว่านี้ = ว่าง | รอยลบถูกนับเป็นคำตอบ → เพิ่ม; ฝนจางหาย → ลด |
| `CONFIDENCE_THRESHOLD` = 0.60 | ต่ำกว่านี้ flag ว่าไม่มั่นใจ | flag มากเกินไป → ลด |
| `BIN_ADAPTIVE_C` = 25 | ความเข้มที่นับเป็นหมึก (สูง = เข้มงวด) | รอยลบ/เงาติดเป็นหมึก → เพิ่ม; ฝนจางหาย → ลด |
| `BUBBLE_SAMPLE_RATIO` = 0.75 | ใช้วงในกี่ % ของรัศมี | เส้นขอบวงติดเข้ามา → ลด |

วิธีจูน: รัน `evaluate.py` แล้วเปิด `reports/eval_…_errors.csv` ดูคอลัมน์ `ratios` ของข้อที่ผิด
เปรียบเทียบกับช่วง ratio ของวงว่างและวงที่ฝน แล้วเลือกเกณฑ์ที่อยู่กลางช่องว่าง ใน dashboard เมนู "ตั้งค่า"
ปรับ 3 ค่าแรกแล้วกด "ตรวจใหม่ทั้งหมดด้วยค่าใหม่" ได้ทันทีโดยไม่ต้องประมวลผลภาพซ้ำ
(รายละเอียดการจูนรอบนี้อยู่ใน `DECISIONS.md` ข้อ 31–35)

## ข้อจำกัด

- **ยังไม่ได้ทดสอบกับภาพถ่ายจริง** — ตัวเลขข้างบนมาจากภาพสังเคราะห์เท่านั้น ภาพจริงอาจมีกระดาษโค้ง แสงสะท้อน
  ภาพเบลอจากการสั่นมือ ซึ่ง synth จำลองได้ไม่ครบ
- กระดาษต้อง **เรียบ** — warp ด้วย homography เดียวจึงแก้กระดาษโค้ง/ยับมากไม่ได้
- ถ้ามาร์กเกอร์โดนบัง ระบบใช้ขอบกระดาษแทนได้ แต่ต้องเห็นกระดาษครบทั้งแผ่นบนพื้นที่ตัดกัน และแผ่นนั้นต้องตรวจทาน
- ฝนจางมากระดับเดียวกับรอยลบ แยกกันไม่ได้
- สถานะ FAINT เกิดขึ้นน้อย เพราะ binarize ทำให้ฝนจางส่วนใหญ่กลายเป็นหมึกเต็มวง (ยังอ่านคำตอบถูก แต่ไม่ถูก flag)
- ไม่รองรับ PDF สแกนหลายหน้า
- ข้อความไทยใน PDF: reportlab ไม่จัดตำแหน่งวรรณยุกต์ขั้นสูง บางตัวอาจลอยเล็กน้อย
- ระบบบันทึกผลให้อัตโนมัติทุกครั้งที่ตรวจเสร็จ/แก้ไขผล แต่ถ้า deploy บนเซิร์ฟเวอร์ที่ไฟล์ไม่ถาวร
  (เช่น Streamlit Community Cloud) ไฟล์ที่บันทึกไว้จะหายเมื่อแอป restart — ต้องดาวน์โหลด Excel เก็บไว้
- YOLOv8n เทรนจากภาพสังเคราะห์เท่านั้น — ใช้เป็นความเห็นที่สองเพื่อ flag ให้ผู้ตรวจดู ไม่ใช่ตัวตัดสินคำตอบ
- YOLOv8n บน CPU เพิ่มเวลาประมาณ 220–270 ms ต่อแผ่น และโหลดโมเดลครั้งแรก ~3 วินาที (ปิดได้ในเมนู "ตั้งค่า")

## นำขึ้นเว็บให้ใครก็ใช้ได้ (deploy)

ไฟล์ในโปรเจกต์พร้อมขึ้น [Hugging Face Spaces](https://huggingface.co/spaces) แล้ว (ฟรี RAM 16 GB พอสำหรับ YOLOv8n)
ส่วนหัว YAML บนสุดของไฟล์นี้คือค่าตั้งของ Space และ `requirements.txt` ใช้ `opencv-python-headless`
จึงติดตั้งบน Linux ได้โดยไม่ติด `libGL.so.1`

**ขั้นตอน**

1. สมัคร https://huggingface.co แล้วกด **New Space** → SDK เลือก **Streamlit** → ตั้ง Visibility เป็น Public
2. อัปโหลดไฟล์ทั้งโปรเจกต์ผ่านปุ่ม **Files → Add file** (หรือ `git push` ไปที่ URL ของ Space)
   ต้องมี `models/omr_problems_yolov8n.pt` (6 MB) และ `samples/demo_sheet.jpg` ไปด้วย
3. ไปที่ **Settings → Variables and secrets** → เพิ่มตัวแปร `OMR_PUBLIC` = `1`
4. รอ build ประมาณ 5–10 นาที แล้วแชร์ลิงก์ได้เลย

**โหมดสาธารณะ (`OMR_PUBLIC=1`) เปลี่ยนอะไรบ้าง**

| เรื่อง | ปกติ (ในเครื่อง) | โหมดสาธารณะ |
|---|---|---|
| บันทึกผลลงไฟล์ | บันทึกอัตโนมัติใน `results/sessions/` | **ไม่เขียนไฟล์เลย** ภาพและคะแนนอยู่ในหน่วยความจำจนปิดหน้าเว็บ |
| ปุ่ม "บันทึกผล" / รายการผลที่บันทึกไว้ | มี | ซ่อน เหลือแค่ดาวน์โหลด Excel |
| ข้อมูลนักเรียน | อยู่ในเครื่องผู้ใช้ | ไม่ตกค้างบนเซิร์ฟเวอร์ ผู้ใช้คนอื่นไม่เห็นข้อมูลกัน |

เปิดโหมดนี้ในเครื่องเพื่อทดลองได้ด้วย `OMR_PUBLIC=1 streamlit run app.py`
(Windows PowerShell: `$env:OMR_PUBLIC=1; streamlit run app.py`)

**ข้อควรรู้**

- ผู้เข้าเว็บที่ยังไม่มีกระดาษคำตอบ กดปุ่ม **"ลองด้วยภาพตัวอย่าง"** ในหน้าอัปโหลดภาพเพื่อดูผลได้ทันที
- Space ฟรีจะ "หลับ" เมื่อไม่มีคนใช้ ครั้งแรกที่เปิดอาจรอสักครู่
- ถ้าเครื่องที่ deploy มี RAM น้อย (เช่น Streamlit Community Cloud ~1 GB) ให้ปิด YOLOv8n ในเมนู "ตั้งค่า" — ระบบยังตรวจได้ตามปกติ

## แนวทางพัฒนาต่อ

- เก็บภาพถ่ายจริงพร้อม ground truth แล้วจูนค่าใหม่ด้วย `evaluate.py --real`
- วัดความเข้มจากภาพเทา (ไม่ใช่ binary อย่างเดียว) เพื่อแยก FAINT ได้แม่นขึ้น
- ปรับพิกัด bubble เฉพาะจุด (local refinement) เพื่อรองรับกระดาษโค้งเล็กน้อย
- ประมวลผลหลายแผ่นแบบขนาน, รองรับหลายชุดข้อสอบ (ชุด ก/ข) ด้วย bubble รหัสชุด
- เทรน YOLOv8n เพิ่มด้วยภาพจริง และเพิ่มคลาส เช่น นิ้ว/วัตถุบังกระดาษ, กระดาษยับ
- ถ่ายภาพต่อเนื่องจากกล้องเว็บแคม/มือถือแบบ real-time
